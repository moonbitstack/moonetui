Why moonetui

Everything a terminal interface needs, on a core that fits in a microcontroller's flash.

⟳

Synchronous by design

No async, no event loop you can't see. The host drives one step(): poll, parse, dispatch, lay out, compose, diff, write.

▚

A real design system

Selectors, specificity and cascade over name, id and class — the CSS model you already know, applied to the terminal.

⇄

Differential renderer

Two frames become only the spans that changed, then only the escape sequences needed — efficient on any wire.

⌗

Unicode-honest

A generated width table measures every line: CJK double width, emoji, combining marks. Padding is never a guess.

▤

Layout that adds up

Fixed, percentage, auto and fractional sizes along an axis, plus a grid with spans and gutters — integer division that loses no column.

✓

Tested on four backends

The same suite runs on wasm, wasm-gc, js and native, so a regression in one world fails loudly everywhere.

Where it runs

The core is pure and portable; only four operations touch a platform — write, read, raw mode, and the size query. Bring your own terminal: a real one through the C library, a canvas in a browser, a Node pipe — or a serial line with no cursor addressing at all.

Getting started

One command to add the toolkit, three to see it run.

Install

moonetui is published on mooncakes under the moonbitstack account:

# in your MoonBit project
moon add moonbitstack/moonetui

Run the examples

Small ones to see a piece at a time, one complete application with tabs, timers and a command line, and the same app on three runtimes — plus a gallery of every widget and a bare-wire demo of the plain serial line:

# a complete little application — tabs, timers, a command line
moon run --target native src/examples/monitor

# a real terminal (Unix or Windows)
moon run --target native src/examples/tui

# under Node
moon run --target js src/examples/hello

# in a browser — open it directly
start src/examples/browser/index.html

# every widget, rendered one after another
moon run --target native src/examples/gallery

# the same app as whole frames of text — a bare serial line
moon run --target native src/examples/uart

A first application

Widgets are values. They render a line at a time, report what they want through typed messages, and never call back into your code:

let button = @widget.Button::new(" Press me ")

let w : &@widget.Widget = button
let ctx = @widget.Ctx::new(1, @geom.Size::new(20, 3))
w.handle(ctx, @widget.Msg::Key(@event.Key::of(Enter)))
// ctx.asked() == [Pressed(id=1)]

Compose them in a tree, style them with a stylesheet, and drive the frame loop from a driver — the architecture page lays out the pieces.

What the library expects of you

  • A Driver for your terminal — or one of the three shipped.
  • A stylesheet if you want one — plain styles work without.
  • A message handler that answers the widgets' typed messages.
docs / architecture

Architecture

Eleven packages, one direction of flow, four points of contact with the platform.

The frame, step by step

The core is synchronous. wasm-gc has no async, and the core must run there — so the main loop is a step() the host drives: a blocking poll on native, setInterval under Node, requestAnimationFrame in a browser.

poll → parse → dispatch → lay out → compose → diff → write
  • poll — the driver reports what arrived, bytes or ticks.
  • parse — @input turns the byte stream into events: CSI and SS3 sequences, modifiers, SGR mouse, bracketed paste, UTF-8 split across reads.
  • dispatch — the app walks the focus ring and hands each event to a widget; widgets answer with typed messages.
  • lay out — @layout and the design system place boxes along an axis or on the grid.
  • compose — @comp turns placements into composed rows of styled cells.
  • diff — consecutive screens become only the spans that changed.
  • write — @style renders the changed styles as differential SGR sequences, and the driver writes them.

The package map

PackageResponsibility
@geomInteger rectangle algebra — Offset, Size, Region, Spacing — with intersection, union, splitting and clamping.
@styleColours (named, indexed, true colour), text attributes, palette quantisation, differential SGR rendering.
@stripOne rendered line: styled segments measured in terminal columns over a generated Unicode width table.
@eventKeys, mouse reports, paste, resize and focus as plain values.

@driverThe seam to a terminal, plus a headless terminal for tests.
@layoutAxis placement and the grid — spans, gutters, integer division that loses no column.
@designThe style system: rules, specificity, cascade, inheritance, chrome.
@widgetThe widget contract and the widget inventory.
@appThe widget tree, focus ring, scroll containers, docks, grids, screens, timers, and the frame loop.

The widget contract

A widget is a value with four operations. No callbacks, no inheritance, no hidden state:

pub(open) trait Widget {
  fn render_line(Self, Int32, @geom.Size) -> @strip.Strip
  fn hint(Self, @geom.Size) -> @geom.Size
  fn handle(Self, Ctx, Msg) -> Bool
  fn focusable(Self) -> Bool
}

render_line draws one row — the compositor asks only for rows it can see. hint reports the size the content wants. handle takes a message and answers through the Ctx: typed outputs like Pressed, Changed, Selected, Highlighted, Toggled — which a handler can claim before the app acts on them.

docs / design

Design system

The CSS model you already know — selectors, specificity, cascade, inheritance — applied to the terminal.

Rules and cascade

Give a node a name, an id and classes; write rules against them. Rules stack by specificity — id 100, class 10, name 1 — then by position, and a node inherits the text style of its container:

let sheet = @design.Stylesheet::new()

sheet.add(
  @design.Sel::new(name="Header"),
  @design.Styles::new(text=Some(@style.Style::new(bold=true, fg=@style.cyan))),
)
sheet.add(
  @design.Sel::new(classes=["framed"], focus=true),
  @design.Styles::new(border=Some(@design.Heavy)),
)
  • Selectors — name, id, class, and the :focus, :hover and :disabled pseudo-classes.
  • Properties — border, padding, margin, alignment, display, dock, grid spans, offsets, transitions, scroll-bar styles, and the text style itself.
  • Chrome — borders, padding and margins draw behind the children, so a framed container never clips its own frame.
  • States — a node the pointer rests on takes :hover; a disabled one takes :disabled and neither focus nor input.
  • Transitions — an offset moves a node without telling the layout; a transition glides it to wherever the next layout puts it.

Scroll containers and docks

A pane sizes its child to the child's own content, shows a window of it, draws bars that track the window, and moves by wheel, by the arrow, page, home and end keys, and to whatever just took focus. A docked child sits against an edge of its container, over the flow that gives up the space.

Drivers & terminals

Four operations touch a platform: write, read what is available, set raw mode, and ask for the terminal size. Everything else is pure.

Shipped drivers

DriverEnvironmentNotes
@driver/nativeA real terminaltermios on Unix; virtual terminal mode on Windows.
@driver/nodeNode.jsRaw mode, a queue the data handler fills, a frame pump on the clock.
@driver/webBrowserA terminal on a canvas — a grid of cells, its own escape handling, key encoding, resize in-band.
@driver (headless)TestsA terminal that understands the sequences — the whole suite runs against it.

The three terminal worlds

▮

Bare serial UART

A microcontroller and a wire. No cursor addressing, no colour: pass plain=true when the app is built and the renderer sends whole frames instead of diffs — the same cell buffer, written line by line, nothing but text and newlines. Bring a Driver that writes bytes; nothing else changes.

▤

Serial-era terminals

Anything speaking the classic control set: cursor movement, erase, and the eight-colour palette. moonetui emits only the ECMA-48 / ISO 6429 subset these terminals understand — SGR (CSI … m) for style runs, CUP (CSI H) for addressing — and quantises true colour down to the palette the far end actually has.

_rgba

Modern terminals

The full feature set: true colour, box-drawing glyphs, double-width CJK and emoji, bracketed paste, SGR mouse reports, focus events. The differential renderer keeps the wire quiet between frames.

Standards

  • Unicode — every line is measured in terminal columns over a generated width table: wide CJK characters, double-width emoji, combining marks. Alignment and padding are never guesses.
  • ECMA-48 / ISO 6429 — the control sequences moonetui emits follow the international standard for control functions for coded character sets: SGR for character attributes, CUP and friends for cursor addressing, ED for erase. A terminal built to the standard renders moonetui output without negotiation.
  • UTF-8 — the input side decodes UTF-8 incrementally, so a code point split across two reads arrives whole.

What the suite covers

  • Geometry and strips — rectangle algebra, clipping at character boundaries, Unicode width.
  • The parser — CSI and SS3 sequences, modifiers, mouse, paste, split UTF-8, against a headless terminal.
  • The compositor — rows from placements, diffs from consecutive frames, spans to escape sequences.
  • Layout and design — axis and grid placement, the cascade, inheritance, chrome behind children.
  • Every widget — each one's keyboard contract, message shape and rendered rows asserted against expected text.
